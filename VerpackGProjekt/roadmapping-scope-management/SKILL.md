## Key Concepts Across All Sources

### Shape Up Methodology (Basecamp)

**Core Principles**:
- **Appetite**: How much time we want to spend (not estimates)
- **Fixed time, variable scope**: Time boxes are sacred, features are flexible
- **Shaping before building**: Senior designers/programmers shape work before teams start
- **Small senior teams**: One designer + 1-2 programmers for 6 weeks
- **No backlogs**: Ideas that matter will come back
- **Hill Charts**: Visual representation of uncertainty and progress

**Three Phases**:
1. **Shaping**: Define boundaries and risks before building
2. **Betting**: Decide what to build in the next cycle
3. **Building**: Teams work autonomously to ship

### Strategic Roadmapping (Aha!)

**Core Components**:
- **Vision**: Long-term direction and purpose
- **Strategy**: How you'll achieve the vision
- **Goals**: Specific, measurable objectives
- **Initiatives**: Major efforts to achieve goals
- **Features**: Capabilities that deliver value
- **Releases**: Time-based groupings of features

**Roadmap Types**:
- Business roadmap (strategic priorities)
- Portfolio roadmap (multiple products)
- Features roadmap (detailed capabilities)
- Technology roadmap (technical evolution)
- Go-to-market roadmap (launch activities)

### MoSCoW Prioritisation

**Framework**:
- **Must have**: Non-negotiable, system won't work without it
- **Should have**: Important but system works without it
- **Could have**: Desirable, easy to defer
- **Won't have this time**: Explicitly out of scope

**Benefits**:
- Clear prioritization language
- Stakeholder alignment
- Explicit scope boundaries
- Risk management

## Quick Reference: Key Practices

### From Shape Up

**Shaping Work**:
- Use breadboarding (not wireframes) for interaction design
- Use fat marker sketches (not pixel-perfect) for visual ideas
- Define elements, not full specs
- Mark rabbit holes explicitly
- Set boundaries with appetite

**Building Work**:
- Start with one vertical slice (front to back)
- Integrate continuously
- Track progress on Hill Charts
- Scope hammer to fit in time box
- Ship at end of cycle (no extensions)

### From Aha! Roadmapping

**Strategy Before Roadmap**:
- Define clear vision statement
- Set measurable goals (with timeframes)
- Identify key initiatives
- Score and prioritize features
- Link everything to strategy

**Communication**:
- Tailor roadmap views to audience
- Business roadmap for executives
- Features roadmap for development
- Timeline roadmap for launches
- Now/Next/Later for flexibility

### From MoSCoW

**Applying the Framework**:
- Start with business objectives
- Identify Must-haves first (typically 60% of effort)
- Distribute Should/Could based on capacity
- Be explicit about Won't-haves
- Revisit as you learn

## Example Workflows

### Workflow 1: Shape Up Six-Week Cycle

```
Pre-Cycle (Shaping):
1. Senior designers/programmers shape for 2-4 weeks
2. Create pitches (problem, appetite, solution, rabbit holes, no-gos)
3. Present pitches to betting table

Betting Table:
4. Review all shaped pitches
5. Consider: Does problem matter? Is appetite right? Right people available?
6. Make bets on 2-4 projects
7. Post kick-off message with pitch

Six-Week Build:
8. Teams get oriented (1-3 days)
9. Integrate first vertical slice quickly
10. Use Hill Charts to track progress
11. Scope hammer as needed
12. Ship at end (deploy to customers)

Cool-Down (2 weeks):
13. Fix bugs, explore, plan next cycle
14. No scheduled work
```

### Workflow 2: Strategic Roadmap Creation

```
Foundation:
1. Define product vision (long-term direction)
2. Set strategic goals (measurable, time-bound)
3. Identify key initiatives (major efforts)

Prioritization:
4. Gather feature ideas from all sources
5. Score features (value, effort, strategic alignment)
6. Apply MoSCoW to create clear priorities
7. Sequence work by dependencies and capacity

Roadmap Creation:
8. Map features to releases/timeframes
9. Create multiple views (business, features, timeline)
10. Link features to goals and initiatives
11. Build in flexibility (Now/Next/Later)

Communication:
12. Present business roadmap to executives
13. Share features roadmap with development
14. Create timeline roadmap for launches
15. Update regularly, communicate changes
```

### Workflow 3: Feature Prioritization

```
Prepare:
1. List all feature requests
2. Gather context (user needs, business goals, technical constraints)

Apply MoSCoW:
3. Identify Must-haves (system doesn't work without)
4. Identify Should-haves (important, but system works)
5. Identify Could-haves (nice to have, easy to defer)
6. Explicitly list Won't-haves (out of scope)

Validate:
7. Review Must-haves: Are they truly essential?
8. Check capacity: Can we deliver all Must and Should?
9. Get stakeholder alignment
10. Document priorities and rationale

Execute:
11. Build Must-haves first
12. Add Should-haves as capacity allows
13. Consider Could-haves only if ahead
14. Revisit Won't-haves for future cycles
```
